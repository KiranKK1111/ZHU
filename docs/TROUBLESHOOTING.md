# Troubleshooting

Logs: `%LOCALAPPDATA%\app.zhu.desktop\data\logs\engine.log`. `GET /api/system/diagnostics` returns versions, GPU state, the selected speech model, and the event sequence.

| Symptom | Cause | Fix |
|---|---|---|
| "Speech model failed to load: mkl_malloc: failed to allocate memory", or "CUDA failed with error out of memory" with plenty of VRAM free | Not enough **host** memory (RAM + page file, the "commit charge"). CTranslate2 reads and converts the whole model in RAM while loading. Measured on the RTX 5060 laptop: it failed with ~1.5 GB of commit free | Close memory-heavy apps (dev servers, browsers with many tabs), or let Windows manage the page file (System → About → Advanced system settings → Performance → Virtual memory). ZHU automatically retries with INT8, then smaller models, then CPU, and the error message shows the measured free memory |
| "NVIDIA graphics driver not installed" (setup screen, Settings → Listening, and a notice at start) | Windows sees an NVIDIA card but its driver is not installed, so neither CUDA nor NVML can see it. ZHU lists the graphics cards the way Device Manager does; the log has a `graphics cards:` line with each card and its state | Install the driver (**Get the driver**, or Windows Update), then restart ZHU. Until then speech recognition runs on the processor and ZHU recommends a smaller model |
| "NVIDIA graphics card turned off" / "not working" | The card is disabled in Device Manager, or Windows reports a problem code for it | Turn it on in Device Manager → Display adapters, or reinstall its driver, then restart ZHU |
| "NVIDIA graphics driver needs an update" | The driver is installed but CUDA does not start with it | Install the latest driver from NVIDIA (550 or later), then restart ZHU |
| "Graphics driver not installed" (Intel or AMD) | Windows uses its basic display driver for that card | Install the driver through Windows Update or from the maker. Speech recognition uses the processor on these cards either way |
| "Local transcription is running in CPU mode." | No CUDA device, an old driver, or nothing fits the VRAM budget | Update the NVIDIA driver (≥ 550), or pick a smaller speech model (Settings → Listening → Speech recognition → Change) |
| Parakeet runs on the CPU although a GPU is present | Less than 4 GB of memory (RAM + page file) was free when listening started, the VRAM budget is under 2.8 GB, or precision is set to INT8. `GET /api/listening/status` reports the model, device, and selection reason | Usually fine: Parakeet on the CPU is fast (about 0.1 s per utterance, see BENCHMARKS.md). For the GPU, close memory-heavy apps, then stop and start listening |
| "Speech model failed to load … E_OUTOFMEMORY" (Parakeet on DirectML) | Not enough host memory for the DirectML load (about 3.5 GB) | ZHU retries the same model on the CPU automatically (about 1.5 GB) |
| "No speech model is installed yet." | Model setup was skipped | Settings → Listening → Speech recognition → Change, then Download |
| Model download fails | No network, a proxy, or blocked `huggingface.co` | Retry. Partial files resume. Behind a proxy, set `HTTPS_PROXY` for the user account |
| "Download failed: 'NoneType' object has no attribute 'write'" | Builds before the fix: the engine runs inside `zhu.exe`, which has no console, and the download library wrote its progress bar to the missing console | Update ZHU. The engine now gives such writes a place that discards them, and the progress bar is off (progress is measured from the files) |
| "The local engine stopped" notice, or "not running" at launch | The engine's run ended with an error (the reason is under **Show the details**), or its files are missing or blocked by antivirus | Click **Restart engine** (also in Settings → App and the tray menu), check `logs\engine.log` in ZHU's data folder, and allow ZHU's folder in your antivirus. "The engine in ZHU's folder is incomplete": reinstall ZHU |
| "ZHU closed unexpectedly while its engine was starting" | Last time, ZHU ended by itself within a minute of starting its engine: a crash inside one of the engine's native libraries (speech recognition, graphics) takes the whole app with it. To avoid a crash on every start, the engine was not started | Click **Restart engine**. If ZHU closes again, choose a different speech model in Settings → Listening, update the graphics driver, and send `logs\engine.log` |
| **Restart ZHU** instead of Restart engine | The engine did not stop when asked, and a new one cannot start in the same process while it is busy | Click **Restart ZHU**: it closes ZHU and opens it again |
| No system-audio transcript | **Listen to** is set to Microphone only, nothing is playing on the selected output, or the wrong output device | Start listening with **System audio and microphone** or **System audio only** (while listening: Settings → Listening → Listen to). Then Settings → Listening → System audio: choose the speaker or headset you are actually listening on |
| No transcript of what you say | **Listen to** is set to System audio only, or the wrong microphone | Start listening with **System audio and microphone** or **Microphone only** (while listening: Settings → Listening → Listen to). Then Settings → Listening → Your microphone |
| Microphone "reconnecting" | The device was unplugged, is exclusively owned by another app, or is blocked by Windows privacy settings | Windows Settings → Privacy → Microphone → allow desktop apps. ZHU reconnects automatically |
| Transcript is empty on silence / "Thank you." never appears | Expected: hallucination guard (AUDIO_PIPELINE.md) | — |
| Questions complete too early or too late | Pause thresholds | The defaults suit most speakers. They can be changed through the settings API (`questions.*`, CONFIGURATION.md) |
| A technical term is wrong (e.g. "Post gress") | Missing vocabulary alias | Use **Edit wording** on the question. Aliases can be added through `PUT /api/vocabulary` |
| While ZHU is hidden the pointer stops at ZHU's edge, and a second arrow moves instead | Expected: the frozen pointer (USER_MANUAL.md → Pointer). Viewers of a screen share see the pointer stand still | Leave ZHU and the pointer glides to the arrow and moves again. If a click or drag inside ZHU does not behave, switch off Settings → App → **Freeze the pointer while hidden**. `logs\shell.log` has a `pointer:` line each time it starts and stops |
| A hidden ZHU cannot be resized | Builds before 2026-11-23 froze the pointer short of the window's edges, so it came back on the page instead of the resize border | Update ZHU. Take the arrow to the very edge (the real pointer appears there) and drag |
| ZHU is running but not in the taskbar, Alt+Tab or the system tray | **Hide from taskbar, Alt+Tab and screen capture** is on (the eye button in the title bar) | Press the eye button again. Minimized, click the floating icon first; or start ZHU again from the Start menu, which brings back the running window |
| ZHU opens hidden (no taskbar button, no tray icon) | It was hidden when it closed: ZHU opens the way it closed | Press the eye button in the title bar. Started with Windows it is minimized: click the floating icon first |
| ZHU is on screen but missing from a screenshot, a recording or a screen share | The same switch: while ZHU is hidden, Windows leaves its windows out of captures | Expected. Switch the hiding off as above to have ZHU in the capture |
| ZHU still shows in a capture, or as a black rectangle, while hidden | Windows older than 10 version 2004 shows a black rectangle; a tool that does not capture through Windows' compositor may show the window | Update Windows, or minimize ZHU before capturing |
| ZHU's main window stays above every other window | The same switch: while ZHU is hidden, the main window stays on top so it cannot get lost | Minimize it to get it out of the way, or switch the hiding off as above |
| ZHU is see-through | The opacity in the title bar is below 100%, or ZHU is hidden (hide mode starts at 80%, or at the level it had if ZHU opened hidden) | Opacity button → **Back to 100%**, or show ZHU again with the eye button |
| A hotkey doesn't work | Another app registered it | Settings → General → Keyboard shortcuts: click it and press a different combination |
| Chat tab: "… is showing its sign-in page" or "No message box found" | You are not signed in on that site yet, or it shows a consent or verification page | Open the tab, sign in (once), and open a chat. ZHU never types into sign-in pages. Then **Send to chat** on the question's card |
| Signed in to one chat site, but another still asks you to sign in | Expected: each site (ChatGPT, Claude, Gemini, …) has its own accounts, and no site can use another site's sign-in | Sign in once on each site. With the same **Continue with Google** (or Microsoft, Apple) button on each, the sites after the first ask only which account to use. Each one then stays signed in, in every tab and after restarts |
| **Continue with Google** (or Microsoft, Apple) does nothing in a chat tab, or a link in an answer does not open | Builds before 2026-11-24 refused every window a chat page opened: the sign-in window and new-tab links | Update ZHU. A sign-in window now opens as its own window and closes itself when done; links open in your normal browser. If ZHU is hidden, show it first, since the sign-in window can open behind it |
| A chat site signs you out after every restart | The site ends its own sessions (some do after a period, or when it sees a new device), or **Sign out of all chat sites** was used | Sign in again; ZHU keeps the site's cookies in its chat profile. If it happens on every restart for one site, say which site |
| A provider refuses sign-in in a chat tab ("This browser or app may not be secure") | Some providers (Google for some accounts) block sign-in in application-embedded browsers | ZHU does not work around this. Use that provider's API (Providers), or its site in your normal browser |
| Chat tab: "this page did not accept the screenshot" or "attachment not confirmed" | The site allows attachments only after sign-in or on a paid plan, or shows no preview ZHU can detect | Check the draft in the tab. If the image is missing, use **Copy image** on the screenshot and paste it yourself |
| A resume upload says "a picture of text … no text recognition for your languages" | The file is a scan or a photo, and Windows has no text recognition installed for your languages | Add a language with its optional features under Windows Settings → Time & language → Language & region, or upload a PDF with selectable text, a Word or a text file |
| The resume was read with mistakes (names, numbers, dates) | It came from a scan or photo, or from an unusual PDF layout | Click the resume card: the preview shows the text read from a picture or a Word file. Upload a clearer file (a PDF or Word file exported from your editor reads best) with **Replace** |
| While ZHU is hidden, two-finger scrolling on the touchpad does nothing in ZHU (or scrolls the program beside it) | Windows sends a touchpad swipe to the window under the real pointer, which stands beside ZHU while the pointer is frozen. Fixed in this version: a tiny window of ZHU's stands under the real pointer and passes the swipe on to the arrow | If it persists, scroll with the mouse wheel or switch off Settings → App → **Freeze the pointer while hidden** |
| While ZHU is hidden, what you type goes to another program | ZHU was not brought to the front by your click (Windows refuses that at times when another program, often one running as administrator, has the keyboard). Fixed in this version: the click is then made a real one | Click into ZHU again; if it persists, switch off Settings → App → **Freeze the pointer while hidden** |
| A chat site's answer does not use the resume | The question went into a chat that was already under way (the resume goes with the first question of a **new** chat), or its switch is off | Start a new chat on the site: the next question brings the resume. Pointing at the tab shows what happened to it ("Resume attached", "added to the message") |
| The question did not appear in a chat tab | Automatic delivery is off, you were not listening, the tab is not in the target ("Selected tab"), or the site changed its page | The options button at the right of the chat tab strip; pointing at the tab shows the last result. **Send to chat** on the question's card retries |
| The chat page disappears while a menu or dialog is open | ZHU's own menus would be hidden behind the native page, so the page is hidden meanwhile | Expected; it returns when the menu closes |
| ZHU uses a lot of memory with many chat tabs | Each loaded tab is a full web page (150–400 MB) | Close tabs you do not need, or set **Send to: Selected tab** |
| Custom model: "rejected the API key (or requires one)" / "model or endpoint not found" | The server needs a key, or the endpoint URL is not the OpenAI-compatible base (usually ends in `/v1`) | Settings → AI models → that model → Manage: fix the address or add the key, then **Connect** |
| A screenshot cannot be sent in Custom chat: "… cannot read images", or the gateway answers "model or endpoint not found" | The selected model is text-only. A gateway answers "not found" when a picture is sent to such a model | Press the **Use …** button in the message box, or pick a model that reads images (on Kilo Gateway, for example `nvidia/nemotron-3.5-super-vl:free` or `openrouter/free`). The list of which models read images is taken from the gateway the first time a screenshot is sent, and on **Connect** |
| "Connect" worked but no model was chosen | The provider lists no model ZHU recognises (its line-up changed) | Pick one from the dropdown that appears under the key |
| A Custom chat answer says "The model … is overloaded or temporarily down at … (HTTP 503, tried 3 times)" | The service that runs the model is busy or down. Free models often are at busy times; the quoted words are the provider's own reason. ZHU already asked three times | Wait a minute and press **Try again**, or pick another model with the chip in the message box and then **Try again**. HTTP 502 ("could not get an answer from") and 504 ("took too long") mean the same in practice. Each failure is logged in `engine.log` (without your question) |
| "… stopped responding" or "closed the connection before the answer was complete" | The provider's connection broke off, or nothing arrived for 2 minutes | **Try again**. If it keeps happening on one provider, choose another |
| A free model answers "rate limit" quickly | Free tiers allow few requests per minute and per day | Wait, or connect a second provider and pick one of its models with the chip in the Custom chat's message box |
| Provider "rate limit or quota reached" | API quota, billing, or rate limit | Wait for the shown retry time, or check billing on the provider's console. API usage is billed separately from chat subscriptions |
| Provider "rejected the API key" | Invalid or revoked key | Settings → AI models → Manage → paste the new key → Connect |
| A screenshot shows black areas | DRM-protected content (video players and some browsers) | Expected. ZHU does not bypass content protection |
| SmartScreen warning on install | Unsigned build | See INSTALLATION.md §5 |
