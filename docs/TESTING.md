# Testing Strategy

| Layer | Command | What it covers |
|---|---|---|
| Engine unit + integration | `cd engine; .venv\Scripts\python -m pytest` | Question engine (all 20 §18 scenarios + per-stage units + manual ops + restart recovery), storage (migrations, crash recovery, revision-guarded upserts, cascades), API (auth, Host and CORS checks, sessions, questions, settings validation, providers without keys, WebSocket auth + replay, vocabulary, purge), event hub (sequence, replay, gap, slow subscribers), providers (SSE streaming, images, 429 + Retry-After, cancel, unsupported capabilities, Anthropic error mapping and message shape), DSP (vectorized high-pass vs. reference IIR, resampling + DC removal), model selection ladder, log redaction, screenshot store, VAD on real speech |
| Question-engine evaluation | `python -m evaluation.evaluate [--dataset evaluation\question_heldout.json]` | Precision, recall, F1, kind / category / format accuracy, follow-up resolution, sub-question counts, confidence calibration |
| STT benchmark (GPU) | `python benchmarks\stt_benchmark.py --e2e` (Whisper); `--configs parakeet-v2-dml,parakeet-v2-cpu,parakeet-v3-dml,parakeet-v3-cpu --e2e --e2e-config parakeet-v2-cpu` (Parakeet) | Load time, VRAM, process commit, latency, RTF, WER (clear, fast, 10 dB and 0 dB noise, two speakers), question detection on real STT output, real-time end-to-end latency. One process per configuration |
| Parakeet back end | part of `pytest` (`tests/test_parakeet.py`) | Catalog and pinned revisions, per-back-end installed-file check, language support, model selection (DirectML / CPU INT8 / memory and VRAM gates / GPU-required), load-failure ladder, SentencePiece word grouping and timing; real CPU inference when the model and benchmark audio are present |
| AI models | part of `pytest` (`tests/test_custom_providers.py`) | Free providers listed first and marked, non-chat models filtered out, automatic model choice from the provider's own list (stable before preview, newest version, nothing chosen when nothing is familiar, a chosen model is kept), a server that rejects the usage option; endpoint URL validation, add / persist / remove, id forgery, limit, keyless requests send no `Authorization` header, API routes (key stored but never returned), survival across an engine restart, and a full run against a real local OpenAI-compatible HTTP server (model list, streamed answer over the WebSocket, stored interaction) |
| Resume, job, screenshots panel | part of `pytest` (`tests/test_resume.py`) and `npm test` (`tests/resume.test.tsx`, `tests/screenshotsPanel.test.tsx`, `tests/sidepanel.test.ts`, `tests/webchat.test.ts`, `tests/webchatOptions.test.tsx`, `tests/titleBar.test.tsx`) | Text from PDF, Word and text files; Word text boxes once and page headers and footers read, tracked deletions left out; a scanned PDF and a small photo read with Windows text recognition (Windows only), and a clear message when it is unavailable; long files cut at a line; unusable files explained (old .doc, damaged files, over 10 MB); neither block can be closed from inside the text. Read once, condensed once: an upload with a model makes exactly one condensing request, later Custom chat messages carry the profile and not the full text (no further request; the request starts the same each time), a new upload is condensed again, a short resume goes as it is, a failure keeps the full text and **Make it again** works, a resume added before any model is condensed after the first answer (which is not held up), chat websites still get the full text, and Claude gets a second cache point at the end of the earlier turns. One resume kept with its file (served inline, never cached; replaced by the next upload; removed with the resume and by purge; opened in its own program), the several resumes of earlier versions reduced to the one in use, corrections and going back to the file's text, the single resume of the first versions kept; the job (typed, from a file, switch); the resume and the job reach the model (a question submitted to a provider, and a Custom chat message) only while switched on, with the question passed unchanged; purge removes them; the text for chat sites changes when the resume does. Claude: the system prompt goes as one cached block (checked on the wire against a local server). Panel: two cards side by side, one file input (not multiple), the preview from the card (a PDF in a frame, Word as its text with Open in Word, a picture with its text, an older resume's text), replace and remove, the switches without opening, the job's card and Remove. Screenshots (`tests/screenshotsPanel.test.tsx`): all of them with no session switch, Delete all beside Capture (asks first), the empty box filling its place. Chat sites: the page helper adds the resume to a new chat only, once, as a file or as text, and keeps it in its own draft. Screenshots in the chat: refused for a provider not set to read images, sent once, text-only history, answer again. Attachments in a message box, where "Add to …" goes (the chat tab that is shown, or a new Custom chat, which opens when no tab is open), and the pointer drag (click vs. drag, drop zones, Escape). Live run with made-up data: [CHAT.md](CHAT.md#resume) |
| Custom chat | part of `pytest` (`tests/test_chat.py`) and `npm test` (`tests/chat.test.tsx`) | Free-model detection (flags, price shapes, ids, local addresses, free tiers), model-list shapes, a free model selected on Connect; conversations against a local gateway-like server (two turns with two models, answer again, provider error and retry, thinking kept apart, rejected requests leave nothing behind, purge, interrupted answers); the model list and default choice, money vs. formulas, rendered Markdown (no HTML, no remote images, links open outside), the chat store, questions reaching the chat's message box. Live run: [CHAT.md](CHAT.md#tested) |
| Front end | `cd apps\desktop; npm test` | The app's client against a real engine, which the test starts from `engine\.venv` on a throwaway data folder and stops again (token check, settings, providers, question events over the WebSocket); WebSocket envelope ordering and dedupe, revision-guarded stores, transcript partial→final replacement, auto-scroll logic, shortcut recording; the question card (one **Send to chat** button); the title bar (`tests/titleBar.test.tsx`: two screens, the chats first; the gear opens Settings, shows as pressed, and goes back to the chats) and listening in it (`tests/listeningControl.test.tsx`: no session controls, what to listen to, the live state, a listening error); the taskbar switch in the title bar (starts in the shell's state, changes only when the shell says so, follows the tray menu, reports a failure); chat tabs: service list vs. page-helper hints, tab ids, https-only addresses, message template, result wording, automatic-delivery gating (listening, switches, dedupe, revisions, target), and the page helper itself on plain text boxes (replace / append / already there, sign-in pages never written to, nothing is ever clicked) |
| Questions beside the chat | part of `npm test` (`tests/webchatQuestions.test.tsx`) | The questions column sits beside the chat tabs, and a card's **Send to chat** sends the question to the chats; collapsing leaves a **Questions** button with the count (and the dot while one is being asked) before the tabs, and the chat area stays the same element when the column collapses or opens (the native page is placed over it); the width (within its limits) and the transcript switch are kept for the next time; with no chat tab open, a question opens one Custom chat tab and shows it, and the tabs that are open are used otherwise (a second Custom chat from the **+** menu is numbered) |
| Typing and scrolling | part of `npm test` (`tests/streaming.test.tsx`) | The typewriter by simulation (bursts every 50 ms, frames at 30–120 Hz): never ahead of the text or backwards, an even pace from bursty input (per-frame variation under 0.35 against over 1.2 raw), about 0.3 s behind a steady stream, a finished answer drained in well under a second, the last characters not crawling, the same speed at any frame rate; the hook (history shown at once, typing of new text, a replaced answer, reduce motion). Markdown blocks: the answer rendered block by block gives the same HTML as rendered whole (lists with blank lines, nested lists, code with blank lines, a multi-line formula, a table, a quote, indented code), no cut inside code, formulas or lists, link references kept whole, and the last block tidied (bold, code, strikethrough, a link's address, a table header, a formula, a lone `-` or `#`). Follow scroll: the glide never overshoots and is frame-rate independent; a list that opens at its end, glides after new content, stops for the reader, keeps their place and comes back with **Latest** |
| Rust shell | `cd apps\desktop\src-tauri; cargo test --lib` / `cargo build` | Chat-tab id, address, and navigation rules; the window style with ZHU hidden from the taskbar and shown again; compiles the window, tray, hotkey, engine-supervisor, and web-chat code |
| Packaging | `packaging\build.ps1` | Smoke-tests the **frozen** engine (readiness, health, GPU detection) before building the installer |

## Not automated (manual QA checklist)

These need a real desktop session, and a person should check them on each release:

- [ ] Main window at 900×600, 1366×768, 1920×1080, 2560×1440, 3840×2160 and at 100/125/150/200% scaling: no clipping, overlap, or horizontal scroll
- [ ] Opacity (title bar): 40% to 100% on the main window, a chat website tab and the floating icon; **Back to 100%**; kept after a restart. Hide mode starts at 80%, can be changed while hidden, and showing ZHU brings back the previous level; closed hidden at another level, ZHU opens at that level
- [ ] Windows Snap by dragging the title bar to an edge, Win+Arrow, double-click maximize
- [ ] One screen: ZHU starts on the chats (the questions column beside the chat tabs, the side panel on the right, the title bar above). With no tab open, the chat area lists Custom chat and the sites
- [ ] Smallest window: dragging an edge stops at 1100 × 690 (at 100% scaling); a smaller size saved earlier comes back at that size after a restart. At that size, side panel open and closed: the questions stay at least 300 px wide and the chats fill everything to their right, with no empty strip, whatever width was dragged or saved; a new Custom chat shows only its greeting (no sample questions); the side panel scrolls as a whole when it must, the empty screenshots box is seen whole, and the resume and job cards sit side by side at one size
- [ ] Resume: upload a PDF, click its card: the PDF is shown inside ZHU (WebView2's own viewer); a Word file shows its text with **Open in Word** (opens Word); a picture shows itself and the text read from it; **Replace** swaps the file, **Remove** deletes it (and `data\resume\` is empty again). The switch on a card changes **In answers** / **Not used** without opening it
- [ ] Title bar, on the chats and in Settings: Start listening, then Live with the timer, Pause/Resume and Stop; a listening error shows a notice and Stopped
- [ ] Settings: the gear (next to the screenshots-panel button) opens it and becomes a house; the house, and Esc, go back to the chats (Esc with a dialog or menu open in Settings closes that first); the tray's **Settings** opens it; a chat website's page is hidden while Settings is open and back afterwards
- [ ] Dividers: drag the one between the questions and the chat and the one above the transcript (the pointer stays the arrow; the accent line shows), with a Custom chat and with a chat website shown; sizes kept after a restart; double-click resets; arrow keys, Page Up/Down and Enter on a focused divider; collapse the column and open it again
- [ ] Send to chat with no chat tab open: a Custom chat tab opens with the question in its message box, nothing is sent; with tabs open it goes to them (all, or the selected tab), and a second press does not open another Custom chat. **Clear** on the questions and on the transcript empties them while listening goes on
- [ ] Screenshots with no chat tab open: the hover button and the large view say **Add to a new Custom chat**; it opens a Custom chat with the screenshot attached. With a tab shown, they name that tab and add it there
- [ ] Listen to: **Start listening** opens a menu of three rows of one size (icon tile, title and line, tick on the last choice); each starts with only those sources in the transcript and is ticked next time; the hotkey and the tray start with the ticked one; while listening, Settings → Listening → Listen to switches between all three (the dropped source's transcript stops and the new one starts within a second, the timer and the session go on), also while paused (nothing is transcribed until Resume)
- [ ] Resume and job: upload a real Word resume with text boxes and a page header (each section once, the name first), a scanned PDF and a phone photo (read, opened for checking); edit, Save, Back to the file's text; a second resume and switching from the name; the job pasted and from a file. Ask in the Custom chat with each switch on and off. With a Claude key: the second question's usage shows `cache_read_input_tokens`
- [ ] Resume on chat sites, signed in (ChatGPT, Claude, Gemini, then the others): the first question in a new chat attaches `resume-zhu-….txt` with the note above the question (or the text, where a site takes no file); the next question in the same unsent draft keeps it, with no second file; after Send, the next question goes alone; **New chat** on the site brings it again; the chat-tab options have no resume setting. A website tab has no strip under the tabs: the page starts right below them, and pointing at a tab shows its last delivery
- [ ] Sign-in windows in chat tabs: on each site, **Continue with Google** (then Microsoft, Apple where offered) opens a sign-in (in a window of its own on sites that use one, which closes itself) and the tab is signed in; the second site asks only for the account. A source link in an answer opens in the normal browser. Restart ZHU: every site is still signed in
- [ ] Tray: show/hide, start/pause listening label, **Restart the engine**, quit (`zhu.exe` gone from Task Manager within a few seconds; `engine stopped` at the end of `engine.log`)
- [ ] One process: while ZHU runs (listening or not), Task Manager shows only `zhu.exe` (no `zhu-engine.exe`, no `python.exe`)
- [ ] Settings → App → **Restart engine** while listening: the window stays where it is, a notice shows the restart, listening stops, the engine is back within seconds
- [ ] Hide from the taskbar, Alt+Tab and screen capture: press Alt+Tab and Win+Tab with it on (no ZHU, no floating icon) and off; switch it from the tray menu; restart Explorer with it on (no taskbar button comes back)
- [ ] The same with a chat website open in a chat tab (its page sits inside the main window): each press of the eye hides or shows at once (tool window, on top, 80 % opacity, left out of captures, and back); minimized while hidden, the floating icon appears and brings ZHU back. Shell code finds the main window with `main_window()` (lib.rs), never `get_webview_window("main")`, which finds nothing once a chat page is in the window
- [ ] Hide mode after a restart: hide ZHU, change its opacity, quit (or end the process), start it again: hidden from the first frame (watch the window's style and display affinity from the moment the process starts: tool window, left out of captures, on top, at that opacity, never an app window) and still at that opacity once the page has loaded; started with `--minimized` it is minimized behind the floating icon; shown again and restarted, it is an ordinary window. `start-state.json` in `%LOCALAPPDATA%\app.zhu.desktop` holds the state; delete it after testing
- [ ] Tray icon while hidden: gone from the tray and its overflow while hidden, back when shown; closing the window while hidden minimizes it (floating icon appears); hiding from the tray menu while the window was closed to the tray brings it back minimized
- [ ] Frozen pointer while hidden: move into ZHU (the real pointer stops at the edge; an arrow that looks like the Windows pointer of the current scheme moves, over the title bar too, never ZHU's violet one); click the gear, scroll the settings, click the Custom chat's message box and type, drag a divider; drag the title bar (the window moves with the arrow, the real pointer stays) and double-click it (maximize, restore); leave to one side (the real pointer glides there in a fraction of a second, no jump); move the arrow onto each edge and drag (the window resizes; dragging inwards does not freeze); press while the pointer is still gliding to an edge (it resizes from there); hide ZHU with the pointer over it (at the first movement the arrow takes over and the real pointer moves off to the nearest edge); show ZHU with the arrow (the real pointer glides to it); a screenshot shows neither ZHU nor the arrow; switch it off in Settings → App and the pointer moves normally over a hidden ZHU. Automated in the debug build: start it with `ZHU_FREEZE_TEST=1` (synthetic input counts as the mouse's) or `=visible` (the arrow also shows in screenshots) and drive it with `SendInput`, absolute moves (the arrow moves by point − where the real pointer is) and relative ones (as a mouse sends them). Make every scripted press check that ZHU is under the arrow or the pointer first, so a slip cannot click another program
- [ ] Pointer: only the arrow over a text box, a button, a link, a pane divider, the window edges and a chat website's message box (no text beam, hand or resize arrows), with Custom pointer on (ZHU's violet arrow) and off (Windows arrow); while hidden always the Windows arrow; typing, dragging dividers and resizing still work
- [ ] Graphics driver warning: on a PC whose NVIDIA card has no driver, the setup screen and Settings → Listening say "NVIDIA graphics driver not installed" with **Get the driver**, a notice appears once at start, and `engine.log` lists the card as `[no_driver]`
- [ ] Model download in the installed app started from the Start menu (no console): progress, then installed
- [ ] While hidden: a full-screen screenshot (PrtSc, Snipping Tool) and a screen share show the desktop behind ZHU's main window and floating icon; after switching the hiding off they show ZHU again; ZHU's own screenshot (Ctrl+Shift+A) taken while hidden leaves ZHU hidden afterwards
- [ ] While hidden: the main window stays above other apps when they are clicked, including a maximized one; after showing ZHU in the taskbar again the main window goes behind other windows normally
- [ ] Global hotkeys with a conflicting app registered
- [ ] Keyboard-only navigation of every screen; screen reader announces the recording state
- [ ] Clean install on a fresh Windows user account; first-run model download; uninstall

Every number in BENCHMARKS.md comes from these commands. Results must not be edited by hand.

## Live desktop test (2026-11-17)

The real app (`zhu.exe` debug + Vite) was run on the development laptop (RTX 5060, Windows 11, 125% scaling) with a throwaway data folder. It was driven through WebView2's DevTools protocol (real DOM clicks and mouse events) and real global hotkeys, with SAPI-synthesized interview audio played through the speakers and captured by system-audio loopback.

| Area | Result |
|---|---|
| Shell starts engine, UI connects (authenticated WebSocket) | ✅ |
| First-run setup: GPU detected, recommendation, low-memory warning, real download (`base`, 147.9 MB) → app switches to the workspace automatically | ✅ |
| Live transcription, large-v3-turbo FP16 on CUDA | ✅ transcript word-perfect, confidence 0.89–0.96 |
| Question detection live: direct, follow-up resolved ("How is HashMap different from ConcurrentHashMap in Java?"), coding task, scenario spanning two VAD segments, acknowledgement not a question, intentional repeats linked | ✅ |
| Uncertain words (low STT probability) shown with dotted underline | ✅ |
| Sidecar: global hotkey show, live transcript, latest question, Pause (engine → paused), compact bar (46 px), edge snap (gap 0), off-screen recovery | ✅ |
| Region capture: overlay, drag, Enter → 650×375 physical-pixel PNG at 125% scaling | ✅ |
| Copy question (button) and copy-latest hotkey (Ctrl+Shift+C) → Windows clipboard | ✅ |
| Light theme; 900×600 minimum: compact layout, no horizontal overflow | ✅ |
| Engine killed → supervisor restart ~1 s, both windows reconnect, session resumable | ✅ |

### Defects found by this test and fixed
1. No minimize/maximize/close on the setup and engine-starting screens → shared `WindowControls`.
2. Context-panel tab label clipped at 125% → 320 px panel, equal-width tabs.
3. Microphone failed to open: WASAPI shared mode needs the native channel count (4) → open with native channels.
4. One capture failure (or listing devices) terminated **all** audio streams: per-caller PortAudio instances were terminated → one process-wide `PortAudioHost`.
5. Scenario lost when split across VAD segments: loopback's sample clock drifted behind wall time and question completion used the wall clock → loopback silence padded against wall time and completion ticks on the audio clock.
6. Engine crash ended the active session → sessions stay resumable (recording never resumes on its own).
7. Overlay window creation failed (0x8007139F) whenever windows had custom WebView2 args → overlay inherits the main window's args.
8. Duplicate sidecar edge-snapping in the front end and shell → shell only.
9. Speech model never released after stop → unloaded after 120 s idle (frees VRAM and ~2 GB RAM for turbo).
10. Memory preflight message was not shown in the UI → displayed on the setup screen.

### Not covered by this run
Tray menu clicks, the native Save dialog (export), provider API calls with real keys (none configured), the microphone path with a human speaker, multi-monitor moves (one monitor available), and the 1024×768–3840×2160 / 100–200% scaling matrix (only 125% available).

## AI chat tabs: live test (2026-11-20)

Debug build on the development laptop, throwaway engine data, driven through the DevTools protocol of both the main webview and the chat profile. **No account was used: every site was signed out.** Results per site, the end-to-end run (speech → question → tabs in 1.8 s; screenshot attached in ChatGPT; nothing submitted), and what was not tested are in [WEB_CHATS.md](WEB_CHATS.md#tested-behaviour).

Also verified live: a chat page cannot call any ZHU command (`engine_info`, `webchat_tabs`, `event.listen`, `clipboard-manager.write_text` all rejected); two tabs of one site share the same cookies; the page area follows the window layout at 125 % scaling; the page is hidden on other screens and after a reload of the main window.

### Defects found by this test and fixed
1. A page that swapped its text box for a rich editor mid-delivery made the helper re-run the image phase and report 0 images → only the text phases restart on a replaced editor.
2. Meta AI collapses its layout to 0 × 0 while the tab is hidden, so its message box was "not visible" → size check skipped for a site's own hinted message box in hidden tabs.
3. **On DeepSeek's sign-in page the question was typed into the phone/e-mail field** → sign-in pages are detected and never written to; single-line inputs are no longer candidates for the generic search.
4. A sign-in page made a delivery wait 30 s → reported after 4 s ("sign-in page"), or after 10 s once a page is fully loaded without a message box.
5. After a page reload the site restored ZHU's unsent draft and the next question was appended to it → the shell remembers the last text inserted per tab.
6. Found in review, not by a failing run: a hidden main window flushed engine events on a throttled timer (up to 1 s late) → flushed in a microtask; show/hide commands could be applied out of order → serialized; a tab closed while its page was still being created left the page running → closed again after creation.

The installer rebuilt with these features (`dist/ZHU-Setup.exe`, 851 MB) was **not** put through the install / uninstall test below again; the install steps did not change.

## Installer test (2026-11-17, `dist/ZHU-Setup.exe`, 844 MB)

Real per-user install on the development laptop, with no test overrides.

| Step | Result |
|---|---|
| `ZHU-Setup.exe /S` | ✅ exit 0, registered in Apps as "ZHU 0.1.0", Start-menu shortcut |
| Launch installed `zhu.exe` | ✅ bundled `zhu-engine.exe` ready in ~4 s, CUDA detected (RTX 5060), first-run model setup shown; no Python, Node or CUDA toolkit used |
| Data location | ✅ `%LOCALAPPDATA%\app.zhu.desktop\data` (db, logs, models, screenshots); the install folder `%LOCALAPPDATA%\ZHU` holds program files only |
| Uninstall **while the engine is still running** | ✅ install folder fully removed in ~2 s, shortcut and registry entry removed, user data kept |

### Defects found by installer testing and fixed
1. NSIS failed (`error mmapping file … out of range`): the 2.0 GB CUDA runtime exceeded NSIS's ~2 GB limit → only the CUDA DLLs proven necessary are bundled (transcripts identical in FP16 and INT8/FP16; a control run without DLLs fails).
2. Program and data shared `%LOCALAPPDATA%\ZHU` (the per-user install folder) → data moved to the per-app data folder.
3. Uninstall left 31–41 locked engine files (97–126 MB) → NSIS hooks stop the engine and wait for it to exit, then sweep the engine folder.
4. Frozen windowed engine could lose the readiness handshake (`sys.stdout` is None) → fd-1 fallback; console logging only when stderr exists.
5. `anthropic` SDK was not a declared dependency → added to `pyproject.toml`.
